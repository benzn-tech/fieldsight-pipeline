## 2. 去重后的想法清单（按 12 个月可卖性排序）

编号沿用切片：A4 = 切片 A 第 4 卡。

### 第一梯队：现有数据的重新出口，不需要新采集

1. **Evidence Pack**（A4 / B1 / C1 / C7）——按 thread / 日期范围 / programme task 导出：quote + 绝对时间 + 说话人置信档 + ±30 s 音频 + 同窗口照片 + 天气 + capture/receive 时间戳 + hash。买家：GC commercial manager、有索赔暴露的分包、QS。**唯一能单独定价的**。前置：Track B；prod 开 `EMIT_EVIDENCE`。
2. **周报 = delta 表**（B5 / C13 / A1）——`新出现 / 持续第 N 天 / 消失或解决`，每行带上周对比和 quote，主题行就是三个数字。同时是 Track S（Signals）的第一个产出面。前置：`SUGGEST_THREADS` prod 打开。
3. **沉默日**（B3 / C5 的 Silence 栏）——工作日 14:00 前无录音 → 一条 10 秒提示"是没开工还是忘了"，答复进 `delay` 域带 `cause_party`。周报单列。这是"没发生"也是信息的最直接产品化。
4. **说话人置信度进邮件**（A3）——三档措辞机械决定："Paul 确认…" / "现场有人确认…（说话人未识别）" / 不进 Assignee 列。避免 Otter 式"给错的人发 deadline"。
5. **当日对账行**（A10 / B9）——确认邮件顶部"今天收到 12 段 / 设备记录 14 段；2 段待上传"。BUG-43 的用户可见面。
6. **contemporaneity 脚注**（B4 / C7）——每条"录于 09:41:12，上传于 09:41:40，未被编辑"。零成本文案。
7. **定价页**（A8 / B8 / C11）——每活跃站点/月，录音端不限或按端，阅读者免费，公开价格；交付后转"保管档"（C7：每工地每年一笔小钱，Glacier 成本可忽略）。

### 第二梯队：小交互改动，需要 App 配合

8. **会前简报卡**（A5）——"本周你会碰到的：Paul（水电）— 3 条未关，上次提及 9 天前"。Track S 的第二个出口。
9. **口头标签**（A11）——固定词表（flag / variation / safety / to QS / 追一下）字面匹配直接写字段，不经模型。先 grep 两周 transcripts 看有没有自发出现。
10. **照片 + 5 秒语音说明**（B12）——拍照后自动进 PTT，把 ±2 min 推断绑定变成声明绑定。和 Track L 互补。
11. **漏录检测**（A2）——收工前比对在册时段 vs 有录音时段，≥2 h 空洞提示补一段。先用 prod `recordings` 一个 SQL 看空洞是否真实存在。
12. **manpower 口头点名**（B6）——抽取模板加 `manpower[]`，只从 site manager 口述抽。
13. **prestart 录音 → register**（B14 / C5）——`meeting_type=prestart`，hazards raised + 口头报数，不做声纹出席。

### 第三梯队：新客户段或新入口，需要 owner 决定

14. **分包商私有记录**（B2 / C2）——"你的记录，你的账户"，口头指令账本 `instruction_received{from, what, time}` + 自动"for record purposes only"邮件草稿。新客户段。
15. **WhatsApp / Teams 群语音条作为 ingest**（B13）——官方 Business API + 群内知情同意，语音条落现有 S3 前缀。降低换习惯成本，尤其对分包。
16. **被录者页 + trust page + 导出保证**（A6 / A7 / A13）——不卖钱，但是 GC 采购问"工人怎么想 / 你倒了怎么办"时的答案。半天到两天。
17. **Bank draw / funder's QS 进度证据页**（C3）——programme task × 佐证碎片 × 照片 × hash 月度一页。取决于能否拿到 1 家 QS 试用。
18. **业主周报**（B11）——**部分违背定位**（给业主看的叙事），但需求证据强且 NZ 无等价物。若做，用 delta 结构，不能全自动发送。

### 长期 / 标记
19. Handover decision trail 给 FM（C6）——2–3 年，依赖 Track B + 一个已交付项目。
20. 保险费折让（C4）——5 年，NZ 无对应保险方。
21. FM/维护巡检近亲（C9）——形状最像，3 个电话再说。

## 3. 三方矛盾与拉伸（如实记）

- **业主周报（B11）vs owner 定位**：它是叙事。B 切片自己标了"部分违背"。C 切片的 Oura/Whoop 证据说叙事被骂、表格被要——所以如果做，形状必须是 delta 表 + 照片，不是作文。两个切片其实一致：**违背的是形式不是需求**。
- **"AI 日报"的地位**：B7 说它 2026 年已商品化（Procore 锁 Premier、App Store 有免费小应用），应降级为"当然有"；但它是今天客户付费的东西。结论：**不取消、不主打**，首页第一行换成证据锚点 / 跨天 / 沉默日。
- **Ask agent**：C14 和 A1 都说"事后搜索"使用率极低、推送才被消费。仓里 Ask 投入不小（scoped ask、conversation memory、web answer、corroboration 都在 9 月做了）。建议：**Ask 维持，不再作为增长重点**；下一季度的产出面预算给周报 delta 和会前简报。
- **照片连拍（A12）**：agent 自己打了低分——手机在口袋里。留作 fake-door。
- **LOKI**：没有叫 LOKI 的 AI 硬件；同音候选是 **Looki L1**（挂脖 AI 相机，always-on 间隔拍照，可关指示灯）。它恰好是 owner 定位的**反面教材**。请 owner 确认指的是不是它。

## 9. 两个客户段的潜在方向（智库补充）

**分包商**（同一条管线，换一个抽取类型和一个收件人）
- 入口：分包工头每天收工那通给老板的电话 → 变成 PTT 或 WhatsApp 语音条（切片 B 卡 13 的官方 Business API 路径）。
- 核心对象：`instruction_received{from, what, at}`——"GC 的谁、在几点、让我做什么"。当天自动出一封"for record purposes only"确认邮件草稿给 GC，工头点一下发。这是分包最缺、GC 最怕的那封邮件。
- 第二对象：daywork / 变更的**当天**记录（人数、机器、时长），带机器时间戳。切片 C 引的判例：GC 拿不出反证时，分包的当时记录就成立。
- 出口：月底一份"本月口头指令 N 条、已书面确认 M 条、未确认 K 条"+ Evidence Pack。
- 定价：按公司包月，工头不限，老板/QS 免费看。
- 红线：不做 GC 方 speaker identity；措辞永远是"你自己的记录"，不是"对付 GC"。
- 先验证：5 个分包工头电话（几点怎么汇报 / 留底吗 / 机器人进群拉吗）。

**开发商 / 业主**（不是住宅建商，是你说的开发商客户）
- 他们不在工地，付钱买的是**知情权和进度证据**。两个产出面：
  - 周报：`做了什么 / 下周 / 什么变了 / 需要你决定什么` 四段，每段带照片和 quote，不写散文（切片 C 卡 13 的 Oura/Whoop 教训）。
  - 月度进度证据页：programme task × 有佐证的碎片 × 照片 × 时间戳（切片 C 卡 3），开发商可以直接转给 funder's QS，少一次现场。
- 关键机制：**"对外可见"标记**。安全事件、分包纠纷、成本讨论默认不进业主视图；抽取时打标 + site manager 发送前复核。不能全自动发。
- 阅读者免费的定价（切片 B 卡 8）在这里最有用：开发商是读者，不是录音者。
- 依赖：Track L（按位置分组）让周报能按楼层/区域排；Track B 让"上周说的这周有没有做"能对上。

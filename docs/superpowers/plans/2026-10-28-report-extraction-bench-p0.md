# Report / extraction bench — P0 (offline tooling) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and unit-test, offline, everything the owner needs to run P1 of the report / extraction bench: snapshot rendering of every candidate prompt, request builders and callers for the six models, a read-only collector, the S3-template check, the two gold pages, the shared ledger with report pools, a dry-run-first runner, scoring with the noise floor F, and select / freeze.

**Architecture:** Bench-only code in `tools/report-bench/`; nothing in `src/` changes. Candidate prompts are rendered from a cold snapshot of `src/` at each sha (`git archive <sha> src`, `python -I` worker with a fixed import-time env) and pre-rendered per session into `--out`, so the live runner never touches git. The runner calls OpenRouter with develop's `llm_utils.build_qwen_payload` body and Claude via the official SDK (streaming, `max_retries=0`), records every attempt, and charges Anthropic dollars to report pools inside the one ledger file shared with the web bench. The owner runs every live / keyed step; every P0 test uses fakes.

**Tech Stack:** Python 3.11. Tests: `C:/Users/camil/fspy/Scripts/python.exe -m pytest` (CI-identical; no `anthropic` SDK — never pip install into it). Live runs: `C:/Users/camil/wt/benchenv` (has the SDK). Pages: static HTML generated by Python, no build step.

**Spec:** `docs/superpowers/specs/2026-10-28-report-extraction-prompt-model-bench-design.md` (rev 2.1), §2-§8.

**Code sharing with the web bench (decision):** copy, do not depend. The sister bench (`tools/web-answer-bench/`, branch `docs/claude-web-answer-bench`, 17 commits ahead of develop, unmerged) is the pattern source; files taken from it are copied into `tools/report-bench/` with a header line `# Adapted from tools/web-answer-bench/<file> @ a61738ef (docs/claude-web-answer-bench); dedupe once both branches are on develop.` Both branches then merge to develop independently in either order. The only coupling is the ledger **file format**, pinned by a test (Task 2).

## Review Focus

1. **Web bench rewrites the shared ledger** → report pools survive its read-modify-write, and the report bench's global check sees web spend. Test in Task 2 (`test_web_style_rewrite_keeps_report_pools`).
2. **An old sha's function has a different signature** (no `speaker_names` / `continuity_block` / `topics`) → the worker passes only accepted kwargs and the hash is still produced; never a TypeError that silently drops a candidate. Test in Task 3 (`test_worker_filters_kwargs_by_signature`).
3. **Owner points the collector at a folder that is not his, or at `_summary`, or a key under a never-write prefix reaches a write method** → refusal before any S3 call. Tests in Task 6.
4. **A run is interrupted half-way (cap hit, Ctrl-C, one call raising)** → every finished run is already on disk (append-per-run JSONL), the rerun skips finished (cell, session, rep) keys, the ledger total equals the sum of recorded Claude $. Test in Task 10 (`test_resume_skips_finished_runs`).
5. **A model item is matched to a gold item that another item from the same run already took** (duplicates) → one-to-one matching; the extra item is not a second true positive. Test in Task 9 (`test_match_is_one_to_one`).

第 5 步的卡片长什么样

卡片只用来做三件事：批准一个要先问人的动作、在几个选项里选一个、补一个系统推断不出来的事实。能推断的不问，单纯的通知也不发卡片。

项目经理不读整份报告，只看要他决定的那 1 到 3 件事。卡片里给出系统的建议，点一下就行。

引用的原话来自第 4 步核对过的录音，点开能听原声，所以他敢直接点。

什么时候必须问人

必须先问人

  • 对外发消息给分包商或业主
  • 把检查标为"通过"（第一版先不做：系统还没有"通过"这个状态）
  • 改进度计划
  • 删除任何数据
  • 把录音归到别人名下

Agent 自己做完

  • 整理录音、写报告
  • 合并重复的待办
  • 提醒快到期的检查
  • 设备掉线后自动重试
  • 同一任务最多试 3 次，还失败就停下转人

防止烧 token：五道刹车

"试 3 次"只管重试次数，不等于只调用 3 次模型：一次尝试里 Agent 可能连续调用好几次模型。所以要分层设上限，任何一层碰顶就停，并且只发一条告警。

1
单次尝试一次尝试里最多调用模型 8 次，超了立刻停
2
同一任务最多试 3 次，间隔越来越长；最坏 3 × 8 = 24 次调用
3
连锁深度决定 → 新事件 → 新卡片，这条链最多转 3 圈，防止互相触发
4
每个公司每天的钱包用到 80% 提醒，用完暂停不紧急的任务
5
熔断同一类错误短时间内大量出现，整条线暂停，只报一次

数字是建议的起步值，上线前按实际用量调。紧急通道：可能伤人的事直接排最前，不受第 4 道刹车和每人推送上限的限制；其余按 时间 → 影响的后续工序 → 复杂度和牵扯人数 排。
